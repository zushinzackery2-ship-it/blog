Helldivers 2 的地图生成方法是：预制资源池提供几何原料，seed 驱动球面 Voronoi、路线、Zone 和 stamp 的空间重组，最后每局烘焙高度图、导航网格和小地图。不是「若干套成品图只换兴趣点」，也不是「地形从噪声函数长出来」——运行时字符串区、插件 ABI 和类型库都指向这条混合流水线。

这是系列第二篇。上一篇处理星球领土图的球面 Voronoi 拓扑；这篇讲整套生成系统怎么组织、各阶段做什么。

依赖顺序总览#

这是数据依赖顺序，不是逐帧调度表。下面各节按这条链展开。

五段生成函数与 pass 调度器#

Steam Build 24036910（Stingray 1.8.0.0）上，generation pass 名保存在运行时字符串区，指令引用把它们钉进五段连续函数：

函数区间大小职责
0xB9B220–0xBA7DBF52,127 字节主阶段调度、输入准备、资源等待、早期地形
0xBA7DC0–0xBAF69430,932 字节Stamp、资源等待、高度与路线
0xBAFAF0–0xBB890236,370 字节flatten、城市与车队路线、heightmap、stamp
0xBB89A0–0xBBA9988,184 字节stamp 旋转、路线距离、zone 高度
0xBBB160–0xBBD18C8,236 字节末段 stamp 生成

同构建的运行时内存映像进一步确认：这五段函数实现的是数据驱动的 pass 调度器。每个 pass 对应一个描述子——+0x8 存 step 函数指针，中间若干偏移绑定输入/输出缓冲，+0x1988 存 pass 名字符串指针。执行期按这张登记表推进。

阶段名按五组排列。第一组是输入与空间骨架：

随后是任务点与地点候选（generate_mission_stamps、generate_extraction_locations、generate_outpost_locations、spread_locations）、Zone 收口（finalize_voronoi、cellular_automata_colony_even_out、fix_unreachable_areas、calculate_mission_boundaries）、stamp 与地形（place_all_subregion_stamps、render_heightmap_voronoi、generate_city_roads）、水体与输出（generate_water、setup_terrain_navmesh、render_playable_area、capture_minimap）。

资源等待点插在计算阶段中间：预制包在生成过程里被排队、等待、消费

cellular_automata_colony_even_out、spread_locations、generate_fbr_for_stamp_rotation 等 pass 在描述子里带有内嵌立即数（例如 CA 相关描述子复现出容量 1024、24、浮点 0.5/1.0）。这些是调度器登记时的常量，具体语义随 pass 实现而定。

资源等待点：预制池嵌进流水线#

第一段函数（0xB9B220 起）里，指令引用顺序给出这样一段子序列：

stamp 资源包的排队（queue_stamp_packages）、等待（wait_for_stamp_packages）和消费（spawn_stamps）嵌在生成逻辑中间，之后还有 flatten、heightmap、route distance。预制块是程序化流程消费的原料，不是加载时自带的整图。

末段的 setup_terrain_navmesh、render_playable_area、capture_minimap、generate_danger_levels 说明导航网格、可玩区和小地图是每局烘焙的下游产物。

字符串里也有 setup_level_to_load、load_testlevel，上下文指向测试与资源预览；生产流水线的主路径仍是上面的 pass 链。

插件接缝：几何在引擎，玩法在游戏#

level_generation 插件（542,296 字节）唯一导出 get_plugin_api：

自定义函数表四个入口：接入 dl_bin、接入 dl_typelib、执行球面 Voronoi、释放结果。几何调用约定：

  1. 输入：连续 float32 x/y/z，stride 12；
  2. 输出：48 字节描述，内含四个动态数组；
  3. 结果所有权归调用者，必须交回配套释放函数。

游戏侧通过 api id 0xE0DE385D 取函数表，缓存进全局槽；释放走表偏移 +0x18，调用者持有结果句柄并在用完后显式回收。

插件字符串里没有 ScenarioSettings、ZoneSettings 或任务/权重词汇；mission stamp、route、flatten、navmesh 等 pass 名全在 game 模块。分工是：插件 = DataLibrary 资源 + 球面 Voronoi 原语；game = planet 布局、region 参数、stamp 放置、seed 推进。

消费者侧地点链：

运行时样本：13 个 LevelGenerationLocation、800 个 stamp 资源、39 条 ZoneWeight 边（全部来自同一地点实例）。Zone 与 Location 的 stamp 资源交集为零，连接靠 zone_id。

上一篇的 26 张领土图全部通过球面 Voronoi 拓扑检查（512 / 1530 / 1020），可作为这类图结构的校验参考。

种子与生成输入#

生成阶段有独立的 seed pass。遥测事件 RestartedLevelGeneration 携带 initial_seed 和 32 位 number_of_restarts，由客户端拼装后上报后端——生成过程记录初始种子，并且可能整体重启。

输入侧字段名包括：param_planet_index、planet_hash、planet_region_hash、planet_environment_hash、level_id、difficulty、enemy_faction、tactical_objective_points、time_of_day。initial_seed 作为 DataLibrary 反射字段喂进生成流程，各 pass 在 seed 之后按登记表依次消费随机选择。

客户端本地生成#

五段函数、pass 调度器、资源等待点和插件几何调用都在客户端 game.dll 里完成；不存在「服务器下发地图几何、客户端只落地」的接缝。服务器侧拿到的是 initial_seed 和重启次数这类回执。

结论#

Helldivers 2 的地图生成方法是：authored 星球模板 + 球面 Voronoi 空间骨架 + 多 pass 地点与 stamp 放置 + 每局地形烘焙。预制 stamp、planet setup、region 配置提供原料；seed 驱动各阶段的随机选择；heightmap、navmesh、小地图是生成下游产物。

自己做同类系统时，最值得照搬的是插件接缝：几何原语独立成模块，输入输出是纯数据数组，所有权用配对释放函数锁死；权重、候选、种子留在数据和消费者侧。生成器换玩法不用动几何代码，几何升级也不牵连任务配置。
