一个水面实体，加载时需要网格和材质，绘制时又需要当前变换与可见性。两类工作发生在不同阶段，最终却使用同一批组件列。

上一篇解释了这些列怎样存储、迁移和切给 Job。这一篇从水面这样的对象出发，看数据怎样进入 Renderer World，又怎样经相机剔除与列表构建交给绘制。

沿托管调用可以读到参数和句柄的传递，沿转换函数可以读到加载完成后的字段写入。两条路径在 Binder 和组件列上会合，场景对象也就从磁盘资源接到了渲染提交。

查询选出对象，相机再决定怎样画#

组件查询先按签名选出 archetype，Job 更新其中的 LocalToWorld。随后主相机、阴影与反射探针还要分别进行剔除和 LOD 选择。同一实体可能参与多个视角，查询命中只是进入后续处理的起点。

剔除入口分配一份 0x1B0 字节的 BeforeCullingParams，填入设备配置、渲染 World 和视角信息。下面列出与这条路径相关的字段，空白区间仍由其余字段占用：

偏移字段作用
0x00 / 0x04deviceType / deviceTier图形设备与档位
0x08sceneRTSize[2]场景 RT 宽高
0x10compoundCharacterLayerMask角色复合层掩码
0x4C..0x4ErenderPathMobile / isCinematicMode / isUICamera相机路径开关
0x68cullingViewUniqueID本相机视角编号
0xC0cullingSystem原生剔除系统
0x108renderEntityManager渲染实体管理器
0x150renderCamera渲染相机
0x168 / 0x16CcullingViewHandle / uiCullingViewHandle主视角与 UI 视角
0x170 / 0x174rayTracingCullingViewHandle / rayTracingTLASHandle光追视角与 TLAS
0x178terrainCullViewHandle地形剔除视角

这里以及后面的值类型字段，都采用相对值起点的偏移：从本批 IL2CPP dump 的标注减去 0x10。托管类的字段则保留对象绝对偏移，二者分别说明。

原生调用完成后，几个 u32 句柄被抄回相机，包括主视角、虚拟纹理反馈和细分信息；有第二份相机数据时，还会保存 UI 视角。后续建列表使用这些句柄。

设计分享中还描述了视锥、LOD、低分辨率深度图和简化遮挡片。它们解释了原生剔除的组织思路；这段托管入口展示的，则是相机怎样把参数交过去、再取回视角引用。

列表构建接收过滤条件，Pass 保存结果句柄#

CreateRendererList 接收视角、渲染标志、光照模式和提交选项，返回一个 u32：

mask / value 成对传递，用于表达渲染标志筛选；具体比较式留在原生实现中。可见枚举则提供了筛选词汇：PreZ、AlphaTest、透明插入点、投射阴影、角色描边、OIT 等属于渲染标志，GBuffer、Forward、ShadowCaster、DepthOnly 等属于光照模式，CrossFade 与 Dither 放在 16 位关键字中。

这些词汇让调用方描述希望生成哪类列表。带 PreZ 的入口一次返回正常列表与前后两段 PreZ 列表；另一种入口直接接收实体指针集合和相机位置，用来处理已经圈定的子集。

Forward 路径有两个容易混淆的容器。ForwardOpaquePassData 是托管类，对象绝对偏移 0x18 / 0x20 放两个 RendererListHandle，0x28..0x38 放五个 ECS 句柄。PassInput 是值类型，相关字段如下：

归一化偏移PassInput 字段
0x28 / 0x2CopaqueList / opaqueEqualList
0x30characterOpaqueList
0x34 / 0x38characterOutlineList / characterOutlineEqual
0x3C / 0x40transparentList / occludedDisplayList
0x94 / 0x98screenCullingRatio / screenCullingRatioDistance
0x9CscreenCullingLayerMask

数值相近的偏移分属不同布局。Pass 构造函数接收列表句柄，绘制函数再连同命令缓冲交给 DrawECSRendererList。从参数到视角、从视角到列表、从列表到 Pass，这条引用关系贯穿了提交过程。

两个 128 位承担不同职责#

组件掩码回答“这块有哪些组件”，用在 ECS 查询。渲染设计分享中的 128 位排序键回答绘制顺序，字段包括屏幕顺序、pipeline、mesh、材质和距离。

托管调用直接暴露的是列表句柄。它没有展示排序键的位域或编码函数。“把容易打断批次的状态放高位”可以解释字典序排序为何有助于聚簇，具体字段顺序仍须由编码实现确定。

草还使用独立的实例列，步长 0x18：hgKeywords 与 batchGroupHandle 各占两字节，之后是 batchGroupKey、sparsity、renderFlags 和两项四字节 padding。草批次键在注册时保存，渲染标志与 mesh 路径共用词汇；它有自己的分批入口。

加载完成后，资源引用补写进组件列#

流式数据先用编号定位 blob。场景块占高 32 位，块内下标占低 32 位：

解码分别取高低半段，再按需要解释为有符号编号。格子和 uniqueKey 也使用高低位组合；组句柄的高半段只保留 16 位，中间 16 位空着，其取值空间因而更小。

字符串与资源句柄通过属性表取得。PropertySerializeId 是三个 u32，共 0x0C 字节：组件下标、属性 id 和子项下标。只传属性 id 的构造函数把组件下标置为 0xFF、子项置为 0。整数编码保留前两项的低 8 位和子项的低 16 位：

转换上下文既能交出映射字节的指针与长度，也能返回字符串和资源句柄。ConvertFrom 使用这些出口，把资源加载结果补入运行时组件。

水面转换函数按状态码选择三种行为：

状态码直接可见的行为按枚举声明顺序推定的转换
1预取网格与配置，返回成功未加载 → 加载中
3选列并写入资源字段加载完成
6直接返回成功卸载 → 未加载

名称对应来自枚举顺序，实际分支比较的是 1、3、6。其余状态返回失败。转换集中在组的状态切换上，资源引用便有了明确的补写时机。

水面列把寻址公式落到具体字段上#

取列先走句柄下标：槽位步长 0x10，读出 archetype id 与行号；再按 0x240 步长定位描述符。水面组件 id 为 30，对应掩码位 0x40000000。对更低位组件做 popcount，得到内联组件表中该项的位置。

水面在状态码 3 时，按 {0xFF, 0, 0} 取网格对象，把实例编号写入 meshID；按 {0xFF, 1, 0} 取配置，把材质下标转为 float 写入 param0.x。矩阵和其他参数由别的初始化或更新路径提供，这段转换函数只写其中几个字段。

之后还会检查掩码第 7 位，并给选中列的 +0x04 置上 0x700。这个写入可以准确定位，标志位的具名含义仍需对应其消费端。

水面贴花也使用两项资源 id 和相同状态码，后面四项动画参数属于其载荷。流式体积则只在加载完成时把第一字节 isEnable 写为 1，卸载时写为 0，走掩码第 61 位对应的列。

这些例子展示了资源引用和运行时开关的补写。原生 AllocateRuntimeChunk 接收路径并处理磁盘加载；列目录、对齐与搬入过程位于那一层。玩法对象另有 MemoryPack 序列化路径，面向的是上层对象数据。

Binder 让资源与当前变换会合#

渲染实体的 RenderBinder 共 0x10 字节：0x00 是自身 Entity 句柄，0x08 是玩法共享数据下标，0x0C 是渲染类别，最后三字节补齐。它让玩法变化能够找到对应的渲染实体。

同一实体的 LocalToWorld 保存当前矩阵 0x00、上一帧矩阵 0x40、层级句柄 0x80、脏标记 0x84 与计算帧号 0x88。更新 Job 据层级数据形成当前变换，上一帧矩阵留给运动向量。
