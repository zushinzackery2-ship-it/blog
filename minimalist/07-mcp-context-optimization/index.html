文本化编辑：让一次修改留下可读的差异

我早期更关注怎样把工具返回压短：重复字段能否合并，长标识能否缩写，一张节点图还能少占多少上下文。这些优化很直观，响应大小也容易比较。

后来更吸引我的，是另一种很朴素的体验：改一个参数，文件里就变一行。打开差异，立刻知道这次编辑做了什么。

对一次读取来说，紧凑很有价值；对反复进行的编辑来说，可读的变化会一直发挥作用。我现在偏向文本化，主要也是因为后者。

一份能读的文件，也可能很难编辑#

把数据保存为 JSON，就已经得到了文本。但如果节点编号随着导出顺序变化，前面插入一个节点，后面的引用都跟着重排，差异依然很难看懂。

这种时候，文件虽然完整表达了状态，却没有很好地表达变化。读者要先排除大量无关改动，才能找到真正调整的参数。

我希望工作文件更接近编辑时的思考：某个节点还是那个节点，一组连接仍然围绕原来的定义展开。小修改留下小差异，相关修改集中在能够一起理解的地方。

文件采用哪种语法，反而排在后面。真正决定体验的，是读者能否在变化中认出原来的内容。

差异让意图变得具体#

一段聊天记录可以说“让材质更粗糙一点”。文件差异则会留下实际调整的参数，以及与它一起改变的其他内容。

这让讨论有了具体对象。人可以指出某个值改得太多，Agent 可以围绕同一处继续调整。修改之间也能比较：这一版保留了什么，另一版尝试了什么，都不必从对话描述中重新还原。

差异还会压缩审阅时的注意力。读完整个资产和读本次变化，是两种负担很不同的工作。内容越大，能够把注意力集中到改动本身，就越有意义。

因此，文本化对我来说不仅方便模型写入，也改善了人理解模型工作的方式。

文件让工作离开一段对话继续存在#

对话适合讨论，但连续编辑总会积累临时结论、未完成的尝试和已经放弃的方向。工作越长，越难仅凭聊天历史区分当前状态。

文件提供了一个明确的落点。当前内容就在这里，尚未采用的修改也可以单独保留。换一个模型，或由人接手，面对的仍是同一份工作。

这会改变人和 Agent 的关系。人可以直接修正内容，再让 Agent 继续；Agent 也不必独占整个编辑过程。协作围绕作品展开，聊天只是其中一种交流方式。

历史在这里同样有价值。过几天回来看到一处差异，仍然有机会理解当时的选择，而不是只得到一份已经无法解释的最终状态。

文字与画面各自保留长处#

材质参数写得清楚，最终效果仍然要看画面。布局可以由文本表达，空间关系也常常通过视图更容易理解。文本化没有让这些直观判断变得多余。

它提供的是另一种入口：结构和修改可以被搜索、比较与整理，视觉结果则继续帮助人判断作品是否合适。两种形式能围绕同一份内容往返，编辑就有了更多选择。

我现在觉得文本是很舒适的 Agent 工作环境，原因正在这些日常体验里。它让修改容易留下、容易讨论，也容易由另一个参与者接着完成。一次参数调整产生的那几行 diff，看起来很小，却把整个工作过程连接了起来。
