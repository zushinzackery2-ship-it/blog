把照片或插画缩成 24×24 的像素画，常见问题是碎斑：相邻格子分别落成不同颜色，原本连续的头发和衣料变得零散。采样、预滤波和量化都会影响结果；在这里采用的区域优先方案中，处理顺序也发生了变化：先形成色块，再把区域写入输出网格，让相邻格子有机会继承共同的颜色结构。

眼睛、高光和徽章等小特征需要尽早进入这次分配。若合并后只剩区域摘要，单纯在末端补色就很难找回原有形状。下面以一个本地 Python 实现（源码）中的处理与失败样本说明这项选择。

碎斑的成因#

普通缩略图通常希望保留原图的整体观感，这里的像素画重绘还希望形成连续色块、清晰轮廓和有限颜色。分辨率降到 24×24 以后，一个像素的颜色和位置都可能改变形状的读法。

直接对原图做逐格采样或逐格平均，在平坦区域没问题，一到头发、织物、渐变背景这类高频区域就露馅：相邻两个输出格各自独立地取样、独立地聚类、独立地映射调色板，没有任何机制保证它们落到同一个颜色。原图里一块视觉上连续的深棕色头发，输出里变成深棕、暖灰、暗红交错的碎斑。

更合适的采样核、预滤波和量化策略都可能改善结果。逐格决策也能在平坦输入上形成连续颜色，只是它本身没有显式维护相邻格子的区域关系。区域分析补充了这层约束，让连续性成为可以直接控制的目标。

处理链#

处理链拆成六个阶段，前四个阶段都在回答同一个问题——“这张图由哪些连续区域构成”，直到第五阶段才出现输出网格：

六个阶段也提供了缓存边界。只改变后段的落色参数时，可以复用仍然有效的区域与网格结果；换图或改变上游分析条件时，再重算相应阶段。具体耗时取决于输入、缓存状态与运行环境。

工作分辨率与尺寸分档#

区域分析采用中间的工作分辨率。原图过大会增加超像素和合并开销，直接在 24×24 输出上分析又容易提前丢失细节。中间尺度让结构信息与计算量之间多了一项可调节的选择。

工作长边按输出宽度分档：

输出宽度工作长边
8–23pxclamp(输出 × 8, 96, 192)
24–39pxclamp(输出 × 5.5, 128, 224)
40–63pxclamp(输出 × 6, 160, 384)
64–256pxclamp(输出 × 4, 256, 768)

24px 输出对应的工作长边为 132px，正方形输入才会得到 132×132 的工作图，其他输入保持原有宽高比。缩放使用预乘 alpha 的 LANCZOS，然后转 LAB。区域分析主要在 LAB 中比较颜色，因为编码后的 sRGB 数值距离很难直接对应感知差异。

超像素与区域合并#

工作图先用 SLIC 构造超像素，以颜色距离和空间距离共同组织候选区域。连通性还需要相应的检查或处理，不能仅由聚类目标保证。区域预算影响划分规模，原有 24px 焦点样本中得到约 249 个输出区域。

超像素之间的合并由代价函数驱动，代价不只看颜色差，还乘上面积、主体显著性和特征重要度。这样合并天然偏向”吃掉背景里的大片相近色”，而对主体上的小区域保持克制。实现上用一次性构造的紧凑边数组加并查集做合并，替代 Python 动态 set 和堆的图结构——这一层是整条链的性能主体。

合并前保留小特征#

眼睛、嘴、高光、徽章这类小特征，可能在合并阶段被相邻大区域吞掉。若后续只保留合并后的摘要，补回颜色仍缺少原来的形状依据。保留上游信息或重新检测可以尝试恢复，但在这条管线中，提前保护比事后重建更直接。

所以锚点检测放在合并之前：先找出”需要在低分辨率存活的位置”，把它们的重要度写进合并代价，让锚点所在的小区域活到栅格化。候选按主体权重和空间多样性排序——主体上的锚点优先，同一个部位不重复占配额。

锚点判据本身踩过一个坑：最初用 Hessian 主曲率找”小而突出”的点，结果平顶的小色斑（虹膜、徽章中心这类内部平坦的特征）响应太弱被漏掉。后来改用支持域内的局部少数派颜色作为候选依据：一个颜色在邻域里占比小但成团存在，就有机会进入锚点筛选。这样能找回部分平顶特征，再结合主体权重与空间分布分配名额。

覆盖投票栅格化#

栅格化阶段把工作分辨率的区域标签写入输出网格：每个输出格按覆盖面积投票，选择区域并继承其颜色摘要。相邻格子因此拥有共同的落色依据。不过，细长或狭窄区域仍可能在粗网格上断开，连续的输入区域并不保证栅格化后自动连通。

在大色块底层之上，再叠一个稀疏覆盖层：结构锚点强制写入自己的颜色并标记 protected，后续调色板映射和孤立像素清理都不允许动这些格子。前景、背景、alpha、protected 四个语义都是显式布尔掩码，不依赖浮点概率的隐式转换。

区域双色模型与线性光混色#

区域摘要如果只保留一个代表色，冷暖结构在这一步就丢了。头发在受光面偏暖、背光面偏冷，压成一个均色后，后面的调色板和抖动无论怎么做都恢复不出这个关系——信息已经不在管线里了。

所以每个区域保留两组由图像估计的颜色端点，以及混合比例和对比度。端点由区域内像素聚类得到，并非人工指定的冷暖对。栅格化时，各格重新估计局部比例，再根据混合目标选择颜色空间。

这里采用线性光混合，以近似像素覆盖的光量平均。直接在编码后的 sRGB 中平均，通常会得到更暗的中间值；Lab 插值则服务于另一种感知路径。线性光并不保证所有颜色组合都更鲜艳或更符合像素画风格，结果仍需结合端点、比例和观看尺度判断。

这条”双色端点从区域规划一路传到调色板”的链路，是下一篇调色板与色点渲染的输入，这里不展开。

像素预算与焦点构图#

24×24 一共 576 个格子。完整立绘放进去，表情只能得到很少的空间，需要强烈概括。更换取景可以把更多格子分给脸部，因此构图与算法一起决定可读性；增加后处理复杂度，不能无限弥补空间预算。

处理方式是显式构图选项：默认保持原图边界和宽高比，不替用户裁切；用户显式选择 focal 时，用语义模型（u2netp ONNX）的主体概率约束候选范围，在 80×80 的 LAB 图上配对高色度同色相特征对来定位脸部窗口，取约 65% 短边的方形特写。检测到唯一可信正脸时用脸中心接管窗口位置；找不到焦点就退回主体质心。

一个实际教训：焦点检测曾把真实人像照片里的橙色宇航服徽标误判成眼睛，脸被裁出画面。后来增加了人脸 landmark 通道，由检测到的脸部位置决定取景。未命中人脸的既有样本继续沿用原路径，修复前后的输出哈希相同。

放大图与实际展示中的差别#

区域数、锚点保留率和冷暖格子数记录了处理链的变化，却没有直接回答脸是否还认得出来。一个虹膜锚点即使被保留，旁边的暗线和高光也可能挤在一起。把原图、裁切源图和成图放在一起看，才容易发现问题来自取景，还是来自落色。

放大网格能看清一个孤立点是怎样留下来的，实际展示大小则更接近读者对色彩和形状的感受。同一张图里，放大后醒目的两种颜色，缩小后可能已经混成一片；一个看似突兀的亮点，也可能恰好让眼睛有了方向。对于本来就以整数倍放大的像素画，放大后的整体观感同样属于作品本身。

结论#

区域优先方案把几项重要选择放到信息仍然充分的阶段：合并前保护小特征，栅格化前组织色块，调色板构建前保留颜色端点。这样能减少后续重建已经丢失的信息，也让最终差异更容易追溯到具体阶段。
