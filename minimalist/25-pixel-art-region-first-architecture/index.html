把照片或插画缩成 24×24 的像素画，核心失败模式是碎斑：相邻输出格各自命中不同颜色，画面变成噪点拼盘。根源不在采样核的好坏，而在决策顺序——每个输出格独立决策，格与格之间没有任何约束。修复方式是把处理顺序反过来：先在工作分辨率上形成连续色块，再把色块投票写入输出网格；需要在低分辨率存活的小特征（眼睛、高光、徽章）必须在区域合并之前介入决策，合并之后再补救只能改颜色，救不回结构。这套架构落地在 PixelForge 里，一个本机 Python 服务，WebUI 与 Unity 编辑器共用同一条处理链。

碎斑的成因#

像素画和普通缩略图的判定标准不同。缩略图只要求”远看像”，像素画要求连续色块、清晰轮廓和有限颜色——每个像素都是一次显式的落色决策。

直接对原图做逐格采样或逐格平均，在平坦区域没问题，一到头发、织物、渐变背景这类高频区域就露馅：相邻两个输出格各自独立地取样、独立地聚类、独立地映射调色板，没有任何机制保证它们落到同一个颜色。原图里一块视觉上连续的深棕色头发，输出里变成深棕、暖灰、暗红交错的碎斑。

问题不是采样核不够好。换 LANCZOS、加双边滤波、先模糊再缩小，都只能压制碎斑的幅度，不能消除成因：逐格独立决策本身就无法产生”连续色块”这个输出性质。色块是格与格之间的约束关系，必须由一个看得到整片区域的阶段来生成。

处理链#

PixelForge 把处理链拆成六个阶段，前四个阶段都在回答同一个问题——“这张图由哪些连续区域构成”，直到第五阶段才出现输出网格：

六个阶段同时是缓存边界：每个参数只失效它实际影响的最早阶段及下游。只换调色板或色点模式时，前五个阶段全部命中缓存，重算在 100ms 以内完成；改一张图才需要从头跑。

工作分辨率与尺寸分档#

区域分析不在原图上跑，也不在输出分辨率上跑，而是在一个中间的工作分辨率上。原图太大，超像素和合并的开销没有意义；输出网格太小，24×24 上根本不存在可供分析的”区域”。

工作长边按输出宽度分档：

输出宽度工作长边
8–23pxclamp(输出 × 8, 96, 192)
24–39pxclamp(输出 × 5.5, 128, 224)
40–63pxclamp(输出 × 6, 160, 384)
64–256pxclamp(输出 × 4, 256, 768)

24px 输出对应 132×132 的工作图。缩放使用预乘 alpha 的 LANCZOS，然后转 LAB——后续所有颜色距离、对比度和冷暖判断都在 LAB 空间做，sRGB 的数值距离和感知距离偏差太大。

超像素与区域合并#

工作图先用 SLIC 切成超像素：以颜色距离加空间正则聚类，保证每个超像素本身是连续的。超像素数量由区域预算反推，24px 焦点构图下最终得到约 249 个输出区域。

超像素之间的合并由代价函数驱动，代价不只看颜色差，还乘上面积、主体显著性和特征重要度。这样合并天然偏向”吃掉背景里的大片相近色”，而对主体上的小区域保持克制。实现上用一次性构造的紧凑边数组加并查集做合并，替代 Python 动态 set 和堆的图结构——这一层是整条链的性能主体。

结构锚点必须先于合并介入#

眼睛、嘴、高光、徽章这类小特征，在低分辨率下的死法非常固定：合并阶段被相邻大区域吞掉。事后再”把眼睛的颜色补回去”是无效的，因为吞并发生后，眼睛作为独立几何已经不存在，补色只是在错误的形状上涂正确的颜色。

所以锚点检测放在合并之前：先找出”需要在低分辨率存活的位置”，把它们的重要度写进合并代价，让锚点所在的小区域活到栅格化。候选按主体权重和空间多样性排序——主体上的锚点优先，同一个部位不重复占配额。

锚点判据本身踩过一个坑：最初用 Hessian 主曲率找”小而突出”的点，结果平顶的小色斑（虹膜、徽章中心这类内部平坦的特征）响应太弱被漏掉。换成支持域内的局部少数派颜色判据后稳定——一个颜色在局部邻域里占比小但成团存在，就是需要保护的特征，与它是不是”尖”无关。

覆盖投票栅格化#

栅格化阶段把工作分辨率的区域标签写入输出网格：每个输出格覆盖工作图的一小片像素，按区域覆盖面积投票，获胜区域拿走这个格子。格子的颜色来自区域摘要，而不是这片像素的重新平均——这一步就是”区域优先”的兑现：输出格从区域继承颜色，格与格之间的连续性由区域的连续性保证。

在大色块底层之上，再叠一个稀疏覆盖层：结构锚点强制写入自己的颜色并标记 protected，后续调色板映射和孤立像素清理都不允许动这些格子。前景、背景、alpha、protected 四个语义都是显式布尔掩码，不依赖浮点概率的隐式转换。

区域双色模型与线性光混色#

区域摘要如果只保留一个代表色，冷暖结构在这一步就丢了。头发在受光面偏暖、背光面偏冷，压成一个均色后，后面的调色板和抖动无论怎么做都恢复不出这个关系——信息已经不在管线里了。

所以每个区域保留两组真实颜色端点加混合比例和对比度：端点用降低明度权重的主轴初始化加色度加权 2-means 从区域内真实像素聚出来，不是人工设定的冷暖对。栅格化时每个输出格重新估计自己覆盖范围内的局部比例，需要渐变的格子在物理线性光中混合两个端点。直接平均 sRGB 或 LAB 会产生发灰的脏色——sRGB 是经过 gamma 编码的信号值，算术平均不对应任何光学过程；线性光混合对应真实的光量叠加，中间色干净。

这条”双色端点从区域规划一路传到调色板”的链路，是下一篇调色板与色点渲染的输入，这里不展开。

像素预算与焦点构图#

24×24 一共 576 个格子。完整立绘塞进去，双眼加表情能分到的格子是个位数，无论管线多精细都不够画。这不是算法问题，是构图问题：低分辨率下要先决定”把预算花在哪”。

处理方式是显式构图选项：默认保持原图边界和宽高比，不替用户裁切；用户显式选择 focal 时，用语义模型（u2netp ONNX）的主体概率约束候选范围，在 80×80 的 LAB 图上配对高色度同色相特征对来定位脸部窗口，取约 65% 短边的方形特写。检测到唯一可信正脸时用脸中心接管窗口位置；找不到焦点就退回主体质心。

一个实际教训：焦点检测曾把真实人像照片里的橙色宇航服徽标误判成眼睛，脸被裁出画面。修复靠的不是调权重，而是引入显式的人脸 landmark 通道，并保证未命中人脸时行为与原路径完全一致——验收样本的输出哈希在修复前后不变。

验收口径#

这套管线的每个机制都有自动测试，但自动指标只能证明机制生效，不能证明成图好看。区域数、锚点保留率、冷暖格子数全部达标的图，五官仍然可能不可读。最终判定只有一种方式：原图、裁切源图、1x 成图、放大网格并排目检。

目检本身也有尺度纪律。像素画质量不能用 16x 放大图判定——放大会把正常观看尺寸下人眼积分掉的单像素色点放大成”碎斑”，按放大态观感修图会把有活力的色彩振动全部磨平。24px 是验收尺度；诊断成因时导出 48px，它的信息量足以暴露发肤糊块和区域边界走向，比 24px 好定位得多。与观看距离无关的缺陷才是真缺陷：明度分层断裂、剪影不成立、结构不连续属于这类；孤立饱和色点的放大态观感不属于。

结论#

像素画重绘的质量上限由处理顺序决定：连续色块必须在栅格化之前形成，小特征必须在区域合并之前拿到预算，冷暖信息必须在调色板构建之前保留。三件事都是”把决策提前到信息还在的时候”，末端补救在这条管线里没有位置。
