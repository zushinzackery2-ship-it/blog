使用 Vulkan 渲染的游戏（如《终末地》），在抓帧或调试工具中却可能出现 DXGI/D3D12 相关对象。本文通过静态逆向分析，定位这些对象的来源路径，并给出排查方法。

结论先放这里#

Vulkan 游戏中出现 DXGI/D3D12 对象的最可能来源是 NVIDIA 驱动路径：Vulkan present 经 VK_LAYER_NV_present 进入 Windows WSI 显示栈，nvwgf2umx.dll 具备 CreateDXGIFactory2 能力参与 DXGI factory 流程。这是 Windows 图形栈分层架构的正常现象。Overlay 层可能介入，但只有 NVIDIA 驱动路径具备明确的 DXGI 创建能力。

一、问题描述#

在分析 Vulkan 渲染的游戏时，常观察到以下现象：

  • 抓帧工具（RenderDoc、PIX）中出现 IDXGISwapChain 对象
  • 进程监控工具显示加载了 d3d12.dll
  • 内存分析器中发现 ID3D12Device 实例

这些对象并非由游戏业务代码直接创建，而是来自驱动层或 overlay 层的间接引入。本文通过静态证据分析其来源。

二、Windows 图形栈的分层结构#

理解这个问题的关键是认识到 Windows 图形栈的分层：

Vulkan 是渲染 API，负责”画什么”。Windows 显示基础设施（WDDM/DXGI/DWM）负责”怎么显示到屏幕上”。两者不是替代关系，而是上下层关系。

四、NVIDIA 驱动路径（最可能来源）#

4.1 Vulkan ICD 与 Present Layer#

vulkan-1.dll 通过 nv-vk64.json 找到 nvoglv64.dll。该 DLL 同时承担：

  • Vulkan ICD（标准 Vulkan 驱动入口）
  • VK_LAYER_NV_optimus（双显卡切换层）
  • VK_LAYER_NV_present / GR2608（Present 处理层）

4.2 D3DKMT 边界#

nvoglv64.dll 静态导入 GDI32.dll!D3DKMTEnumAdapters2，且代码区存在 IAT 跳板：

模块边界 API指令
nvoglv64.dllD3DKMTEnumAdapters2jmp qword ptr [rip + ...]

D3DKMT 是 WDDM 用户态接口。Vulkan 驱动枚举适配器，说明它需要与 Windows 显示基础设施交互。

4.3 DXGI Factory 能力#

nvwgf2umx.dll 是 NVIDIA D3D 用户态驱动，具备明确的 DXGI 能力：

模块边界 API指令
nvwgf2umx.dllCreateDXGIFactory2jmp qword ptr [rip + ...]
nvwgf2umx.dllGetDisplayConfigBufferSizescall qword ptr [rip + ...]
nvwgf2umx.dllQueryDisplayConfigcall qword ptr [rip + ...]

CreateDXGIFactory2 是创建 DXGI 对象的标准入口。代码区存在 IAT 跳板，说明这不是单纯的导入表存在，而是实际会执行的代码路径。

4.4 路径总结#

Vulkan present 最终必须进入 Windows 显示栈。NVIDIA D3D UMD 参与 DXGI factory 流程时，会创建或引用 DXGI 对象。这是 Windows 图形栈分层架构的正常行为，不是异常。

八、排查建议#

Vulkan 游戏中出现 DXGI/D3D12 对象时，排查顺序如下：

  1. 确认显卡厂商：NVIDIA 驱动有 Present Layer，AMD/Intel 的架构可能不同
  2. 检查 overlay：关闭 Steam、Discord 等 overlay 后是否仍出现
  3. 抓运行态调用栈：在 CreateDXGIFactory2 和 D3D12CreateDevice 上断点，看 caller module
  4. 区分 D3D11 和 D3D12：D3D11 对象可能来自 overlay，D3D12 对象更可能来自驱动路径

九、结论#

Vulkan 游戏中出现 DXGI/D3D12 对象，通常不是异常，而是 Windows 图形栈分层架构的正常表现：

  • Vulkan 是上层渲染 API
  • Windows 显示基础设施（WDDM/DXGI/DWM）是底层
  • NVIDIA 驱动在把 Vulkan present 翻译成 Windows 显示栈操作时，会创建或引用 DXGI 对象
  • Overlay 层（Steam、OBS）可能介入 Vulkan present，但当前静态证据中，只有 NVIDIA 驱动路径具备明确的 DXGI 创建能力

静态分析可以锁定最可能的来源，精确确认需要运行态调用栈。

分析环境：Windows x64，NVIDIA GeForce RTX 系列 Laptop GPU，驱动版本 32.x 系列。静态证据来自 PE 结构、imports/exports、IAT 引用提取。
