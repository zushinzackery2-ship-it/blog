壁纸折射不是在 CPU 端逐像素偏移再绘制，而是把视口附近的高度场切片编码成纹理，交给 WebGL fragment shader 计算采样偏移。接缝过渡在 shader 里用 smoothstep 混合预生成纹理；纹理不可用时则生成同语义的程序化过渡。WebGL 壁纸层只提交一个全屏四边形，但完整背景还包含波场推进、纹理编码和多层 Canvas 绘制。

高度场纹理编码#

CPU 端的高度场是一个 Float32Array，取值有正有负。完整波场覆盖页面世界高度，但上传前只截取当前视口上下带少量边距的行。纹理宽度等于波场宽度，纹理高度随可见切片变化，并通过 uFieldOrigin 告诉 shader 这张切片在世界波场中的起始行。

梯度驱动偏移#

fragment shader 里最关键的部分是计算每个像素应该偏移多少。思路分三步：

第一步，把页面世界坐标映射到当前高度场切片。屏幕坐标先加上视口滚动偏移，再除以降采样因子，最后减去切片起始行 uFieldOrigin。因此 Canvas 固定在视口时，shader 仍能采到页面世界坐标下的正确波场位置。

第二步，用中心差分算梯度：

gx 是水平方向相邻两个纹素的高度差，gy 是垂直方向的。梯度向量指向水面高度变化最快的方向。

第三步，梯度乘以一个强度系数得到像素偏移量。垂直方向的折射乘以 0.72 的系数让垂直方向的折射稍弱一些，视觉上更接近从上方俯瞰水面的折射比例。还需要设定一个偏移上限（如 18 像素），防止强扰动时壁纸被拉到离谱的位置。

还需要一个死区阈值——梯度低于某个极小值时不做偏移。这避免了水面完全平静时由浮点噪声导致的微小抖动。

折射强度的计算同时考虑了梯度值和高度绝对值。梯度大（水面陡峭）和高度大（水面凸起高）都会增强折射，但两者的贡献曲线不同：梯度占主导，高度做微调。

网格折射#

壁纸折射对每个像素做的不是独立偏移，而是先划分网格，在”格子级偏移”和”像素级偏移”之间做混合。

网格划分方式：把壁纸区域按运行时步长分成格子。格子内所有像素先计算当前格子中心处的偏移量，再计算像素自身精确位置的偏移量，然后按垂直渐变系数做线性插值。

垂直渐变系数从上到下渐变：壁纸顶部趋向于完全用格子级偏移，壁纸底部趋向于完全用像素级偏移。这让靠上的区域呈现明确的”玻璃砖”质感——每块砖整体偏移、边界分明，靠下的区域过渡到连续变形。

网格步长不是固定的 32px。当前桌面路径按 视口高度 × DPR / 1440 缩放，移动路径按 CSS 视口高度相对 823px 的比例缩放，并对结果设置上下限。这样系统缩放、DPR 和设备类型变化时，网格的物理观感不会被一个 CSS 像素常量锁死。步长越大，网格感越强但局部失真也更明显；步长太小则会接近连续折射。

这是一个微妙但重要的细节：它让水面扰动的视觉反馈不只来自壁纸的扭曲，还有网格线的明灭。人眼对线状高亮比面积偏移更敏感，所以网格线明灭往往比壁纸折射本身更先被注意到。

接缝过渡#

壁纸到正文区域之间不是硬切。shader 里有一段专门处理过渡带的逻辑。

start 是壁纸底边位置，end 是底边加上过渡带宽度的位置。在这个区间内，shader 把过渡纹理采样出来，和壁纸做混合。

过渡纹理的坐标也受高度场梯度偏移，所以水面波动时过渡带也会跟着扭曲——视觉上过渡带”浮在水面上”，而不是独立于水面之上。

过渡带还有一个微弱的水平色温渐变：左侧偏暖、右侧偏冷，幅度约 6%。这种级别的调色肉眼几乎看不出来，但去掉以后过渡带在宽屏上会显得过于均匀。

过渡区的设计最容易犯的错误是直接对壁纸做淡出（opacity → 0），那样会出现两层之间的黑边或白边。正确做法是用过渡纹理作为 alpha 来做混合，过渡纹理本身就包含了 Wallpaper 到背景色的渐变路径。

一次 draw call 的边界#

WebGL 壁纸层每帧只调用一次 gl.drawArrays(gl.TRIANGLES, 0, 6)：六个顶点组成一个全屏四边形，没有多 pass，也没有 framebuffer 切换。draw call 数量低只说明 CPU 提交结构简单，不能直接推出 fragment shader 或整套背景的成本可以忽略。

一次 fieldDisplacement() 会读取中心高度和横纵四个邻点，共 5 次高度场采样。普通壁纸像素在主折射路径调用两次，在网格高亮路径再调用一次，源码层面最多形成 15 次高度场采样，外加 1 次壁纸采样；接缝和页面底层分支还会各自调用位移函数，接缝纹理可用时再增加一次过渡纹理采样。实际执行量受分支覆盖范围和 GPU 优化影响，但“每像素约 5 次采样”明显低估了上限。

CPU 端每帧的开销是：

  1. 高度场迭代（上一篇文章的内容）
  2. 扫描并编码视口附近的高度场切片，随后上传单通道纹理
  3. 设置约 30 个 uniform；uniform location 与 attribute location 已缓存
  4. 一次 draw call

这还不是完整帧成本。Canvas 星点、连线、高光、云层和环境层仍在同一 RAF 中绘制；页面开启磨砂时，动态背景上的多张 backdrop-filter 卡片还会增加合成开销。性能判断必须覆盖完整页面滚动，而不是只统计 WebGL pass。

CSS 变量驱动的视觉参数#

shader 里的几个关键视觉参数不是写死的，而是从 CSS 变量实时读取：

CSS 变量用途
--wallpaper-opacity壁纸整体透明度
--wallpaper-dim壁纸暗角强度
--wallpaper-page-bg页面背景色（用于网格线和过渡带混合）

渲染层每帧都会取得这些值并转成 uniform，但 CSS 数值、颜色和过渡背景 URL 都有缓存，不会每帧重复执行完整的 getComputedStyle 与颜色探针。主题或壁纸调色状态变化时，事件会清空缓存并重新派生色板；shader 不需要重新编译。

这种方式把主题状态留在 CSS 层，同时避免把 DOM 样式解析放进每帧热路径。uniform 的值仍按帧上传，但 location 查找只在程序首次使用该名称时执行一次。

离屏壁纸与连续动画#

壁纸矩形离开视口后，主壁纸纹理不再调用 updateFromImage()；已有纹理继续保留，等壁纸重新进入视口时复用或按来源键更新。高度场切片、页面底层 shader 和 Canvas 动画仍持续运行，因为正文区域的网格、焦散、星点与交互波纹仍依赖它们。

这条优化没有在滚动时冻结动画，也没有降低视觉参数。在 1463×823 / DPR 1.75、磨砂开启的本地 Chrome 连续滚动验收中，优化后约为 66.7-73.8 FPS，P95 帧间隔约 18.2-18.3ms，未记录到 50ms 以上长任务。该结果只代表这组测试环境，用于验证优化没有把视觉连续性换成静态帧，不应外推为所有设备的性能承诺。

渲染降级#

如果 WebGL 不可用（老浏览器或 context 创建失败），回退到纯 Canvas 2D 渲染。回退路径不在 Canvas 上做真正的折射偏移，而是在壁纸区域按高度场梯度画短线段来暗示水面波动：

这种设计的关键在于模拟层不关心输出最终是被 WebGL shader 读还是被 Canvas 2D 画线段读——模拟和渲染之间没有耦合。加新的渲染方式不需要修改模拟代码，只需要读高度场数组和梯度接口即可。
