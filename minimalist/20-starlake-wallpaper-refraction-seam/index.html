壁纸折射不是在 CPU 端逐像素偏移再绘制，而是把高度场编码成一张纹理传给 WebGL fragment shader，让 GPU 在采样壁纸时做坐标偏移。接缝过渡也不是简单的 opacity 渐变，而是在 shader 里用 smoothstep 把一张预生成的过渡纹理混合进壁纸和页面背景之间。整个管线只画一个全屏四边形，所有效果在一次 draw call 里完成。

上传用 texSubImage2D 而不是 texImage2D，区别是前者只更新像素数据而不重新分配纹理内存，每帧节省一次 GPU 内存分配。

梯度驱动偏移#

fragment shader 里最关键的部分是计算每个像素应该偏移多少。思路分三步：

第一步，把屏幕像素坐标映射到高度场纹理坐标。高度场和屏幕有一个固定的分辨率比例（降采样因子），通过这个比例可以从屏幕坐标算出对应的高度场纹素位置。

第二步，用中心差分算梯度：

gx 是水平方向相邻两个纹素的高度差，gy 是垂直方向的。梯度向量指向水面高度变化最快的方向。

第三步，梯度乘以一个强度系数得到像素偏移量。垂直方向的折射乘以 0.72 的系数让垂直方向的折射稍弱一些，视觉上更接近从上方俯瞰水面的折射比例。还需要设定一个偏移上限（如 18 像素），防止强扰动时壁纸被拉到离谱的位置。

还需要一个死区阈值——梯度低于某个极小值时不做偏移。这避免了水面完全平静时由浮点噪声导致的微小抖动。

折射强度的计算同时考虑了梯度值和高度绝对值。梯度大（水面陡峭）和高度大（水面凸起高）都会增强折射，但两者的贡献曲线不同：梯度占主导，高度做微调。

网格折射#

壁纸折射对每个像素做的不是独立偏移，而是先划分网格，在”格子级偏移”和”像素级偏移”之间做混合。

网格划分方式：把壁纸区域按固定步长（如 32 像素）分成格子。格子内所有像素先计算当前格子中心处的偏移量，再计算像素自身精确位置的偏移量，然后按垂直渐变系数做线性插值。

垂直渐变系数从上到下渐变：壁纸顶部趋向于完全用格子级偏移，壁纸底部趋向于完全用像素级偏移。这让靠上的区域呈现明确的”玻璃砖”质感——每块砖整体偏移、边界分明，靠下的区域过渡到连续变形。

网格步长也是一个调参点。步长越大网格感越强，但失真也越严重；步长太小则失去网格效果，退化为连续折射。32 像素是一个视觉平衡点。

这是一个微妙但重要的细节：它让水面扰动的视觉反馈不只来自壁纸的扭曲，还有网格线的明灭。人眼对线状高亮比面积偏移更敏感，所以网格线明灭往往比壁纸折射本身更先被注意到。

接缝过渡#

壁纸到正文区域之间不是硬切。shader 里有一段专门处理过渡带的逻辑。

start 是壁纸底边位置，end 是底边加上过渡带宽度的位置。在这个区间内，shader 把过渡纹理采样出来，和壁纸做混合。

过渡纹理的坐标也受高度场梯度偏移，所以水面波动时过渡带也会跟着扭曲——视觉上过渡带”浮在水面上”，而不是独立于水面之上。

过渡带还有一个微弱的水平色温渐变：左侧偏暖、右侧偏冷，幅度约 6%。这种级别的调色肉眼几乎看不出来，但去掉以后过渡带在宽屏上会显得过于均匀。

过渡区的设计最容易犯的错误是直接对壁纸做淡出（opacity → 0），那样会出现两层之间的黑边或白边。正确做法是用过渡纹理作为 alpha 来做混合，过渡纹理本身就包含了 Wallpaper 到背景色的渐变路径。

一次 draw call 的代价#

整个渲染函数只调用一次 gl.drawArrays(gl.TRIANGLES, 0, 6)——六个顶点画两个三角形组成一个全屏四边形。所有折射、网格线、接缝过渡都在 fragment shader 里完成，没有多 pass，没有 framebuffer 切换。

GPU 侧的开销主要在 fragment shader 的纹理采样次数。每个壁纸区域内的像素大约做 5 次 texture2D，接缝区域额外加 1 次过渡纹理采样。在绝大多数设备上这个负担可以忽略。

CPU 端每帧的开销是：

  1. 高度场迭代（上一篇文章的内容）
  2. 高度场编码并用 texSubImage2D 上传（一张约 384×216 的 LUMINANCE 纹理）
  3. 设置约 30 个 uniform
  4. 一次 draw call

其中第 2 步的 texSubImage2D 是 CPU-GPU 数据传输，理论上是最慢的部分。但因为纹理尺寸很小（得益于降采样），实测影响不大。

CSS 变量驱动的视觉参数#

shader 里的几个关键视觉参数不是写死的，而是从 CSS 变量实时读取：

CSS 变量用途
--wallpaper-opacity壁纸整体透明度
--wallpaper-dim壁纸暗角强度
--wallpaper-page-bg页面背景色（用于网格线和过渡带混合）

渲染层在每帧开头从 DOM 读取这些值，转成 uniform 传给 shader。这意味着切换主题色（亮色/暗色）时不需要重新编译 shader，CSS 变量变了，下一帧 shader 就会用新的颜色。

这种方式比在 JavaScript 里维护一份配置的优点是：主题切换逻辑只需要管 CSS 变量，不需要和 WebGL 层产生耦合。壁纸渲染层只是被动读取、上传、绘制。
