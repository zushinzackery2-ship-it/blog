输入是一个已知的 Unity GameObject。提取链从组件槽取得 Renderer，由 Renderer +0x148/+0x158 读取材质 InstanceID 数组，再进入 Material 属性表取得 Texture2D 引用。CPU provider 有效时走外部只读路径；provider 为空时，在目标 draw 边界从 GPU 读回。抓取时序、格式解码、行序方向和运行态染色分别设置验收条件。

本文给出本次目标构建实际使用的资源链偏移和着色器寄存器映射。它们与模型篇使用同一份二进制 profile，只对该指纹成立；换版本需要重新从符号、反汇编和运行态探针闭合。

处理这类提取，有几条纪律反复被验证：

  • 抓取要在同一快照里原子完成，并按输入资源身份筛掉状态切换的过渡窗口；
  • 解码记录资源格式和视图格式，打包格式按真实位布局解，单通道按硬件采样语义展开；
  • 行序在一个编码边界完成归一化，UV 保持原始值，方向由审计结果验收；
  • 角色材质的最终颜色由贴图、材质常量和像素着色器共同决定；染色逻辑通过反汇编与运行态材质值复现。

下面按抓取、解码、方向、颜色四段展开。

贴图来源与 GPU readback#

CPU 侧 provider 有效时，跨进程读取直接取得像素。provider 已释放时，纹理像素仅存在于显存，由最小注入模块读回目标 draw 绑定的资源。GPU 路径的核心要求是在 API 调用边界取得一份属于同一趟 draw 的自洽资源集合。

锁停在 API 边界，会命中状态切换的中途#

一趟 draw 的绑定由多次 API 调用累积设置：着色器、输入资源、渲染目标、常量依次更新，最后发起 draw。在 API 调用边界取得的锁可能落在过渡窗口，此时着色器和渲染目标已经切换，输入资源仍保留上一趟 draw 的绑定。

着色器和渲染目标属于粗粒度特征，过渡窗口同样满足。大量抽样通常形成资源身份主簇与过渡簇：两者共享着色器和渲染目标，输入槽的资源身份（格式、指针）不同。门控因此加入输入资源身份，过渡簇数据进入拒绝计数。

用输入资源身份做二次筛选#

候选报告层按输入槽资源身份筛选：资源身份匹配主簇时落盘，过渡簇计入拒绝计数。筛选只决定候选是否进入结果集，抓取过程保持原样。

渲染目标拷贝发生在 draw 之前，因此快照保存的是当时已有内容。回放输入采用同一把锁内取得、并通过身份筛选的输入资源、采样器和常量。命中条件选择能够唯一区分目标 draw 的资源身份。

常量和贴图必须来自同一快照#

资源集合还需要满足时刻一致性。逐槽请求会让每个槽来自独立快照，槽与槽之间可能跨过多次 draw。一次窗口请求应在同一把锁内取得全部目标槽、采样器和常量。

窗口请求在同一把锁内、拷贝前完成门控，并一次取得目标范围内的全部槽和常量；门控失败时返回零拷贝结果。常量与参与运算的贴图来自同一快照，使反解代数对应同一趟 pass。门控使用已知资源身份；边长、格式分布等发现性特征留在候选分析阶段。

变换资源先做输入域验证#

输出级变换具有明确的输入域和作用方向。例如某张颜色分级 LUT 实测为压暗曲线，直接应用到离线结果会把画面推向近黑。资源归属确认后，还要继续验证它在渲染链中的数学作用。

验证可使用颜色立方体八个角等已知输入，并通过可解析反解检查残差。压暗曲线的确认会把亮度缺口定位到该变换上游。非线性变换按“逐样本反解，再统计均值”的顺序处理，因为 inverse(mean) != mean(inverse)。8 位显示值同时报告 ±0.5/255 对应的输入区间；误差带覆盖目标比值时，该样本不参与倍率判断。零值与曲线肩部饱和样本也从倍率样本集中排除。

解码要分清资源格式、视图格式与打包布局#

抓回来的字节要解码成像素，这里有三件容易混的事。

  • 资源格式描述底层存储，视图格式决定采样解码。TYPELESS 资源配合 sRGB 视图时，硬件按视图规则执行线性化。抓取结果同时保存两种格式。
  • R11G11B10、R10G10B10A2 等打包格式按真实位布局解码。整型视图直接对应完整像素字，解码后再拆分各分量。
  • A8 等单通道格式按硬件采样语义展开为 (0,0,0,a)，alpha 保留原始数值，RGB 置零。

3D 纹理有两个会静默出错的坐标约定#

以 3D LUT 这类体数据为例，轴序与格号映射需要用偏色样本验收。中性数据满足 r=g=b，无法区分轴排列。

第一是轴序。红/绿/蓝分量分别索引纹理的宽/高/深，而解码后数组的轴顺序往往是（深, 高, 宽, 通道）。因此颜色 (r, g, b) 按 volume[b, g, r] 取值。中性对角线满足 r=g=b，无法区分轴排列；偏色样本负责轴序验收。

第二是格子轴的映射。着色器把编码值夹到 [0,1] 后，通常再映射到纹理坐标区间（如 [0.5/N, 1-0.5/N]），落在首末格的中心。这时“输入值 → 格号”的换算是 cell = coord*N - 0.5。若直接用 (i+0.5)/N 当着色器输入，等于把纹理坐标当成了输入值，每个值偏半格。这类半格误差要靠“编码值 → 格”的正确换算消除，并写进测试，用远小于半格的阈值把反汇编字面量的舍入残差和真正的半格错误区分开。

行序在 GPU、图像与引擎之间的对齐#

纹理从 GPU 显存搬到离线文件、再导入引擎显示，会依次经过几套对“第 0 行在哪、v=0 采样哪一行”约定不同的系统。只要这些约定之间的隐式翻转次数是奇数，画面就整体上下颠倒。

三套系统分别约定 row 0 与 v=0 的位置。D3D11 staging 读回的 resource row 0 对应着色器 v=0 一侧采样到的第一行；PNG 等位图格式把 row 0 放在图片顶部；Unity Texture2D 以底行作为 v=0。API row 0 原样写入文件 row 0 后交给 Unity，净效果产生一次垂直翻转。

方向审计把管线拆成若干边界，并记录每个边界的行序约定与翻转次数。编码边界负责一次归一化，其余环节保持原始像素和 UV 语义。行序、UV 与颜色分别验收。

行序属于编码边界，UV 是网格上的采样坐标，颜色由材质与着色器决定。行序归一化在编码边界完成，UV 逐分量原样保留。

方向要用可判定的审计验收#

方向由可判定的像素对应关系验收。近白底图、纯色底图和对称图案对视觉翻转不敏感，而真实颜色还可能来自运行态材质与着色器，因此画面观感无法单独区分方向、解码和染色问题。

方向正确性由像素对应关系审计给出：确认引擎采样的 v=0 对应文件顶行还是底行，统计各纹理的行序；或比较修改前后的图像，确认差异恰好为一次垂直翻转。该审计覆盖方向，颜色与 UV 分别由独立审计验收。

颜色常常不在贴图里#

部分角色材质使用近白 toon 底图，最终颜色由材质常量和像素着色器合成。通道交换、tint 相乘和解码变体均无法逼近目标颜色时，分析入口转向着色器字节码与运行态材质值。颜色验收由目标染色逻辑回放完成。

编译后的着色器字节码（如 DXBC）在进程堆里以标准容器存在。目标归属沿对象指针链确定：渲染器持有材质数组，材质持有 shader 引用，shader 对象带有名称字段，沿链取得目标字节码后反汇编。着色器 profile、贴图数、材质槽数和输出目标数量用于候选分析。反汇编 API 返回 NUL 结尾缓冲，写入 asm 前按 NUL 截断。

本构建的 Normal 像素着色器已提取到稳定证据：DXBC digest 前缀为 2949ad91d26f，profile 是 ps_5_0，使用 t0/t2/t3/t4/t5 并输出 5 个 SV_TARGET。atlas 门控量 _UVOffset.x 位于 cb1[123].x，实际计算是 uv = uv + cb1[123].x * (remapped - uv)。8 组 palette 的色槽基址依次是 cb1[28]、[38]、[48]、[58]、[68]、[78]、[88]、[98]，对应强度在 cb1[32]、[42]、[52]、[62]、[72]、[82]、[92]、[102]；mask 合成顺序由 asm 钉死为 z -> y -> x -> w。

Face 变体给出了更具体的运行态常量表。cb2 中 _MainColor_0 在字节 0x070（cb2[7]），_MainColor_R 在 0x080（cb2[8]）；_BaseColor_*_1 覆盖 0x0D0..0x100（cb2[13..16]），_BaseColor_*_R 覆盖 0x110..0x140（cb2[17..20]），_BaseColor_*_4 覆盖 0x150..0x180（cb2[21..24]），第 7 组 RGB 在 0x190/0x1A0/0x1B0（cb2[25..27]），第 8、9 组分别在 cb2[29..32] 与 cb2[33..36]，_MainColor_1..9 位于 cb2[37..45]。离线复刻直接按这些位置读取同一 draw 的常量缓冲。

染色复刻里必须精确复刻的三点#

调色板由多组色槽和独立强度组成。着色器按 UV 阈值计算权重，再按权重把色槽合成到底图；复刻依次固定权重签名、通道映射和颜色空间。

第一，权重签名是可组合值。UV 落在跨 tile 区间时，同一像素可能同时命中多个权重，因此图元拆分和缓存使用完整权重 tuple 作为键。第二，mask 通道到色槽的映射和叠加次序由 asm 固定。第三，贴图 RGB 先从 sRGB 解到线性，乘运行态颜色后再编码回 sRGB；mask 通道按原始数值归一化。

组数、区域级联与通道冲突#

染色逻辑还包含组数、区域级联与通道来源三项运行态约束。

同一套着色器可对应不同的调色板组数：完整材质使用多组，简化材质只使用一组全局调色板。离线复刻先读取活动组数；单组材质将该组全局应用，多组材质再按 UV 区域权重索引。这样可以避免零填充组覆盖有效颜色。

部分材质的区域主色采用按固定顺序执行的包含式级联。边界使用包含比较，接缝处可同时命中相邻区域，剩余权重折回默认区。离线实现保持相同的比较方式和执行顺序。

通道来源需要同时记录 asm 采样结论和导出像素统计。一次已确认的例外中，asm 采样 alpha，而压缩纹理的 alpha 近似常量、green 承载空间信息。复刻使用有效数据通道，并在结果中保留 asm 结论、像素统计和例外标记三项证据。

线性运行态颜色被声明成 Color 会二次转换#

运行态上传给着色器的颜色已经处于线性空间。若承载属性声明为会执行色彩空间转换的 Color 类型，引擎会再次转换该值，使亮面压暗。

该属性声明成向量类型并原样上传，着色器保持线性空间计算。sRGB 纹理采样时解码，运行态颜色保持线性参与材质与 toon 光照，最终渲染目标再编码为显示 sRGB。排查时核对承载属性的类型与色彩空间元数据。

MatCap、高光和 rim 等视角相关外观属于实时光照项，逐帧随视角变化。复刻着色器按当前视图计算这些项，贴图仅承载静态纹理数据。

边界与迁移#

这套贴图提取分为四个责任边界：抓取生成同一 draw 的自洽资源集合；解码完成字节到像素的翻译；编码边界统一行序；复刻着色器负责运行态外观。资源身份负责锁定目标 draw，常量与贴图来自同一快照，资源变换经过输入域验证，资源格式与视图格式分别记录，打包格式按位布局解码，单通道遵循硬件采样语义。方向由行序审计验收；染色按权重 tuple、通道映射和线性色彩空间复现。

这些约束共同决定最终产物能否复现目标 draw 的输入与外观。
