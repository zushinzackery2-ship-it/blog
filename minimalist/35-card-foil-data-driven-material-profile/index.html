卡片箔面常见的实现方式是为每种稀有度复制一份材质，再在复制品里调整颜色、纹理和高光。这样视觉变化很快能做出来，但层之间会逐渐分叉：某个 profile 修了彩虹采样，另一个 profile 仍使用旧公式；UI 改了 slider，shader uniform 却没有更新；低质量档静默切换到另一条路径，结果既无法解释也无法测量。

可行的结构正相反：只有一套 WebGL2 ShaderMaterial，八种稀有度由 RarityProfile 数据驱动。Profile 保存 mask 权重、表面参数、虹彩参数、图案、碎闪、动画、色调与 seed；shader 只负责解释这些数据。下面的字段、调试视图和测量口径取自一个卡牌箔面的实现。

Profile主要变化

Ultra名称/图像区域的金属高光

Profile 不保存 shader 代码，也不复制 GLSL。这样修复 sampleSpectralDispersion 或 shardValue 时，所有稀有度共同接受同一修改。

这两个层次不能混为一谈。Mask 决定空间区域；roughness、specular、clearCoat 和 globalIntensity 决定响应强度。把全卡 body 直接并入基础 foilMask 会使整张卡变成过曝色块，所以 body 权重只驱动独立 shard region。

reliefMap.R 是线性高度，shader 对中心、X 偏移和 Y 偏移做有限差分，再在 tangent/bitangent 空间构造局部法线。浮雕区域由 mask 与 uReliefStrength 共同控制；它不能复用 edge sheen uniform，否则调边缘高光会同时改变几何起伏。

贴图色彩空间也有明确边界：

  • card art 与 rainbow LUT 使用 sRGB；
  • mask、height、未来 roughness/pattern 数据使用线性；
  • 输出经 tone mapping 后交给 sRGB renderer。

统一 lighting 层避免“全局加亮”#

箔面的颜色来自角度，而非叠一层彩色噪声。fragment shader 先由法线、光线和视线计算：

  • ambient fill；
  • diffuse；
  • broad specular；
  • sharp specular；
  • Fresnel；
  • 由反射方向形成的 environment band；
  • clear-coat 风格的边缘 sheen。

粗糙度控制宽高光和窄高光的幂次，NdotV 与反射角进入虹彩相位。这样 globalIntensity 只是在已经分层的能量上做总量调节，不会同时放大错误的底色噪声。

Profile 的 uLighting 目前保存主光强度、环境强度和预留高光参数；UI override 会进入 normalizeProfile，再写入最终 uniform。任何控件只更新 DOM、却不回写 uniform，都属于断链。项目测试会直接检查 override 后的 globalIntensity、光强、虹彩、碎闪、pattern scale 和 sheen speed。

Pattern 与 Sparkle 是两个不同尺度#

Pattern 是连续表面图案，可选：

所有模式都先对 UV 乘 patternScale。斜线与交叉线使用周期函数，grid 分别对 X/Y 计算线，cells 使用 cell hash。若只让 patternScale 影响 Voronoi 而不影响 line/grid，UI 看似生效，画面却会保留旧的大线条。

Sparkle 是独立的稀疏闪点：

  1. UV 乘 density 得到 cell；
  2. hash 决定 cell 内位置、半径与闪烁阈值；
  3. uSparkleSeed 决定空间分布；
  4. 时间和 animation speed 决定闪烁。

Seed 与 intensity 必须是两个 uniform。若把 seed 借用 intensity 通道，调亮度会改变闪点分布，profile 切换也无法保持确定性。

Quality 只改变计算密度#

High 使用 profile 原始 cell density；Low 显式降低程序化 cell density，但保留同一个 profile、mask 语义和材质层顺序。质量切换不能静默改成另一种材质，也不能在 WebGL2 创建失败时悄悄降级到 WebGL1。

项目首版把 WebGL2 作为硬前提。无法创建 WebGL2 时页面显示明确错误；shader 编译状态也必须明确报告 ready 或失败，不能在编译失败时仍显示可用材质。

这项约束使性能与视觉差异可解释：Low/High 的变化主要来自程序化计算密度，而不是隐藏 fallback。跨 Unity、Unreal 或 WGSL 移植时，也应保留同样的显式质量参数。

Debug view 是材质的可观测接口#

单看 final 很难判断问题出在 mask、pattern 还是 lighting。统一 shader 暴露六个 debug view：

view内容
base只有印刷卡图
foil-maskprofile 加权后的箔面区域
patternUV 图案原始值
relief浮雕区域与高度影响
rainbow当前角度的 LUT 颜色
final完整组合结果

这些视图共享一个 uDebugView uniform，不复制 shader。它们把常见错误分段：

  • title/attribute/level 翻转：检查 UV 与 mask canvas 的 cardV；
  • 卡外出现颜色：检查圆角边界 discard 与 border mask；
  • profile 变了但 slider 仍显示旧值：检查 UI 状态到 normalize 的同步；
  • pattern 只剩大块线：检查 scale 是否进入全部 line/grid/cell 分支；
  • relief 调节同时改变边缘光：检查 uniform 是否意外复用。

Debug view 也是跨引擎合同的一部分。移植到 HLSL、Material Function 或 WGSL 后若只保留 final，就失去定位层级错位的最便宜手段。

GPU timer query 只在有证据时显示#

浏览器 CPU frame time 不能直接代表 fragment shader 的 GPU 成本。GpuFrameTimer 使用 EXT_disjoint_timer_query_webgl2：

如果扩展不存在、query 创建失败、结果尚未 ready，UI 保留上一次有效值或显示 GPU n/a；如果发生 disjoint，则丢弃当前样本。它不会把 CPU 时间冒充 GPU 时间。

Chrome 151 / Windows 10 / WebGL2 的基线中，Normal high 约 0.07–0.08 ms GPU frame time，Starlight high 约 0.35 ms。这些数字绑定浏览器、驱动、分辨率、质量档和当前硬件，只能作为该环境的验收基线，不能写成普遍性能保证。

自动验证还会遍历八种 profile、Low/High、debug view 和关键 override，确认 shader 编译、profile 参数同步、pattern scale 与 mask 边界没有回归。

跨平台移植保留四份数据#

RarityProfile 不依赖 Three.js、DOM 或场景对象。移植时至少保留：

  1. profile JSON 的字段与单位；
  2. mask 通道及 UV 原点约定；
  3. 线性色彩空间与 rainbow LUT 采样；
  4. 确定性 hash、seed 和 debug view。

Unity 可以把 GLSL 函数改写为 HLSL Custom Function 或 Shader Graph Sub Graph；Unreal 可以把每个材质层拆成 Material Function，再将 profile 映射为 Material Instance 参数；WebGPU 则把 shader 模块迁移为 WGSL 并保持 bind group 语义。

不应把所有层预烘成一张不可解释的颜色噪声。那会丢掉 profile 可调性、debug view 和确定性 seed，也无法验证“普通卡无箔、Ultimate 有浮雕、Starlight 有主体碎闪”这些结构差异。

结论#

数据化材质把稀有度差异放进可检查的参数边界。统一的 mask、表面、虹彩、pattern、sparkle、shard 和 animation 协议让八个 profile 共享组合顺序；独立 seed、色散、浮雕和 body shard 区域避免不同效果互相污染；debug view 让每层都有可观测输出。

再加上显式 WebGL2 能力要求与真实 timer query，材质系统同时获得了三种稳定性：视觉层级可解释、跨引擎语义可移植、性能数字不在缺少 GPU 证据时被伪造。
