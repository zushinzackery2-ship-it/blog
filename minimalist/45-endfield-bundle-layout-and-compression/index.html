外层 VFS 已经交出了正确的文件字节，通用解析器却仍然读不到对象。最小的那个包只有 2461 字节，开头是 40 19 9A FE，没有 UnityFS\0，标准识别方式在文件头就停住了。

继续沿本地 UnityPlayer 的读取函数走，熟悉的资源组织逐渐出现：头部指向块目录，目录描述压缩块和 node，解压出来仍是 SerializedFile 加 .resS。定制处理主要落在字段编码、密码变换和压缩编码上。恢复这些步骤后，原生读取与离线解包得到了相同的资源字节。

这次也改正了一个早期判断。头里的 size 曾被解成一个巨大整数，于是解析器绕过它，改用物理文件长度限制读取。实际指令说明，错误出在旋转方向；正确还原的 size 正是 2461。

先让读取函数真正执行起来#

归档头入口位于原构建 UnityPlayer 的 RVA 0x674090，跳进 .tvm0 的 0x23CBC05。其中一部分指令被搬到启动时生成的代码片段，恢复过程见启动生成篇。恢复虚尾后，调用才能沿原来的续体继续执行。

为了重放文件读取，我把原始 PE 和由本地 EndfieldBase 生成的记录表映射进 Unicorn。文件接口提供样本字节，堆接口负责分配和释放，临界区按单线程调用处理；头部解析、密码轮函数和解压都由目标代码执行。原始 DLL、记录表和输入包分别绑定摘要，执行记录保留实际经过的指令。

头读取函数的第二参数是文件起始偏移。文件接口嵌在归档对象里，读取函数通过它先取头，再定位块目录。这个调用关系把参数、文件位置和字段值放到了同一次执行中。

这个修正让边界重新统一起来：头部声明文件长度，VFS 记录提供文件区间，实际输入流提供可读取的字节数。三者对齐后，再检查目录和每个压缩块是否落在其中。当前安装索引里的 1052 个 Bundle，头部长度都与记录长度一致。

目录和数据块走向不同的解压器#

读取块目录时，原生函数先把 101 字节送入 VFSAES 流变换，再调用标准 LZ4，输出 137 字节。目录里的计数、尺寸、标志和名称继续经过字段还原，才成为归档对象中的 block 和 node。

数据块从 0xA0 读取 2301 字节，走的是另一条路径：先做稀疏 VFSAES，再根据块标志 5 选择定制 LZ4 解压器。原生适配器 RVA 0x668AD0 调用 0x160EAE0，输出恰好 6116 字节。两条链可以写成：

这也解释了早期实验中两种不同的失败。目录未经密码变换就交给 LZ4，会在距离字段失败；数据块做完密码变换后，标准 LZ4 仍会报 distance 22。后一个错误发生在解压阶段，继续调整 key 就偏离了问题。

现在，失败位置可以与实际调用对应起来：目录和数据块各自进入了哪个解压器、输入范围是多少、输出声明多长，都能在同一次原生执行里观察。

定制 LZ4 改变了 token 和距离的编码#

这套方言保留 LZ4 的 literal、match 和扩展长度处理。literal 是直接拷贝的字节；match 是从已输出内容中按距离回拷的一段数据。变动集中在 token 的位布局与距离端序上，下面沿用 LZ4Inv 这个简称。

match distance 则从标准的小端 uint16 改成了大端。token 和距离必须一起解释，否则回拷起点很快就会落到已输出区间之外。

长度达到 15 后，仍然逐字节累加扩展值，遇到 0xFF 继续读取；match 长度最后加 4，重叠回拷也保留。直接重放原生解压器时，纯 literal、距离为 1 的重叠拷贝、超过 255 的距离，以及多字节长度扩展，都恢复出了预期字节。截断输入、输出空间不足和距离越界则返回负数。

一个块与两个 node 拼成完整的小包#

原生目录给出一个压缩块：压缩 2301 字节，解压 6116 字节，标志为 5。两个 node 共用名称主体 CAB-d29c4e95cbb3b4d25d7f11ebc90d49ca，其中 SerializedFile 占 6100 字节，同名 .resS 占 16 字节。

重封装后继续读 Unity 对象#

拿到 node 数据后，可以把容器写回标准 UnityFS：签名 UnityFS\0、格式版本 6、引擎版本 2021.3.34f5。块按无压缩形式存储，块数据 hash 写入解压数据的 MD5，再追加资源字节。

SerializedFile 与 .resS 的内容在这一步保持原样。最小包重封装后长 6319 字节，UnityPy 读到一个 4×4 Texture2D T_default_mro_MRO 和一个 AssetBundle。

早期全组恢复处理过 1048 个包，解析出 19,370 个 Unity 对象；三个大型角色 Shader 包也继续读到了程序结构，见角色湿润篇。这次回到本地原生代码，又让头、目录和数据块的处理有了直接执行依据。VFSAES 的抽取与散回在下一篇展开。
