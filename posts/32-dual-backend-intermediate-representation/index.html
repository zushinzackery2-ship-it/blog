双后端管线的中间表示：确定性起点与有界精修

实时后端与可微后端各自产出结果图时，任何画面差异都无法归因，也无法跨后端重放。可行的做法是在两者之间放一份版本化的强类型中间表示：实时分支给出确定性起点，精修分支只做有界增量，材质终局只实现一次。本文用一条 D3D12 + PyTorch/CUDA 的油画化管线作证据，拆解这份跨后端合同、光谱颜料语义与缓存失效边界。

2026-08-21 20 分钟 4039 字 图形渲染
#D3D12#CUDA#PyTorch#Intermediate Representation#Differentiable Rendering#Shader

同一份输入做两条管线，一条追求实时，一条追求质量，最直观的实现是让两个后端各自产生结果图。这样虽然能并排展示，却没有可靠的比较基础：两边的图元数量、路径、参数与材质公式都可能不同；任何画面差异都无法归因，结果也不能跨后端重放。

可行的做法是把作品定义从渲染后端里抽出来，做成一份版本化的强类型中间表示。实时分支负责分析与确定性规划，精修分支从同一份表示出发、只在有界范围内改动连续参数，优化完成后仍交回同一个材质终局。

这套分层解决三个问题：

  • 两个后端消费同一种图元语义，比较对象是表示本身的差异，不是两套隐含算法的差异。
  • 表示包含完整的资产与参数合同，可以独立保存、校验和重放。
  • 材质只在共享终局解释一次，避免精修分支另写一套“近似”着色。

下面的字段布局、容器格式和验收数字取自一条具体管线——D3D12 实时分支加 PyTorch/CUDA 可微精修分支的油画化渲染，它那份中间表示叫 OilPlan。引用它是为了说明合同该固定到什么粒度，同一套分层不依赖这个具体领域。

两个后端必须汇合在同一份计划上#

精修分支复用实时分支的结果作为起点。服务先用实时分支得到基础计划；若目标调色板仍在 8 色以内，就把同一显示色重建为 31 波段反射率；若需要更多颜料，再重建调色板并把每根笔触的三颜料组合重映射过去。笔触身份、路径与笔刷合同继续沿用。

完成优化后，系统会生成基础、部分混合和完整优化等候选计划，逐个调用同一个 replay_plan 终局，再根据统一指标选择结果。精修分支的可微栅格只负责给优化器梯度，最终交付不使用一套独立的 PyTorch 材质。

运行环境不满足能力时也不改变语义。实时分支与最终回放要求可用的现代 D3D12 后端；精修分支额外要求 CUDA 版 PyTorch 和 8GB 级显存。缺少能力时返回明确错误，不切换到 CPU 近似路径。

强类型合同先于文件格式#

这份表示在内存中对应一个不可变的计划记录：

构造时会检查：

  • 画布尺寸为正；
  • strokes 的 dtype 精确匹配合同；
  • points 是连续的 float32[N, 6]，所有值有限；
  • 每根笔触的 point_offset + point_count 不越界；
  • branch 只能是 shader 或 studio。

检查连续存储有实际后果。D3D12 上传、NumPy 二进制序列化和 PyTorch 参数化都依赖一致的线性布局；允许任意 stride 会让同一计划在三个边界上产生不同解释。

一根笔触由记录和控制点两部分组成#

笔触记录固定为 48 字节，小端布局：

字段类型语义
point_offsetu32在全局控制点表中的起点
point_countu16本笔触的控制点数
brush_id / layer / flagsu16 × 3笔刷、粗中细层与行为标记
seedu32确定性局部随机种子
pigment_indexu8 × 3最多三种颜料索引
pigment_weightf32 × 3三颜料混合权重
opacityf32覆盖强度
thicknessf32厚涂沉积
wetnessf32湿混与高光状态
hardnessf32笔触边缘硬度

控制点每项 24 字节：

位置和宽度都用相对画布的归一化值。分辨率变化时，计划语义不依赖某张固定像素画布；终局根据目标宽高把它解释为像素半径和采样位置。

StrokeRecordV1 · 48 bytes point range offset + count brush / layer flags + seed pigment index × 3 weight × 3 opacity / thickness wetness / hardness

索引全局 points.bin

StrokePointV1 · 24 bytes each x / y width pressure load time

路径与材质参数分离： 控制点可变，笔刷与颜料仍有稳定身份 所有浮点均为 little-endian float32 坐标 / 宽度按画布归一化

路径与材质字段分开后，同一条曲线可以改变压力和载漆而不重建身份；精修分支也能对连续参数求导，同时保留离散的笔刷、图层和颜料索引。

落盘格式必须自带校验#

落盘格式使用 ZIP，但 ZIP 只承担容器职责。固定内容包括：

manifest.json 保存 schema/version、画布与坐标空间、branch、seed、源图 SHA-256、笔触/控制点数量、记录尺寸、调色板维度和单位。除 manifest 本身外，每个文件都记录 SHA-256；读取时逐项重算，不一致就拒绝。

序列化还固定 ZIP 时间戳、文件权限、文件名排序和 JSON key 顺序。因此相同计划与相同笔刷资产会产生确定的容器字节，而不被当前时间或字典遍历顺序污染。

反序列化按固定顺序设卡：先检查 schema 名与版本，再校验文件哈希，按 manifest 维度恢复光谱数组，最后重新构造内存记录以触发合同检查。文件完整性和结构合法性是两道独立门禁。

实时分支的职责是给出确定性起点#

D3D12 分支把源图依次转换为抽象色、切向方向、边缘、显著性与区域，再按 seed 生成粗、中、细三层笔触。方向场决定路径走向，区域阻隔避免笔触跨越主要边界，压力、宽度和载漆沿控制点变化。

确定性在这里有两个用途。第一，参数不变时可重复生成同一份基础计划，缓存和回放才有稳定键。第二，精修分支的质量差异来自优化，而不是每次随机规划换了一批笔触。

笔刷纹理与压力图集也进入计划合同。只保存 brush_id 而不保存笔刷 manifest，会让几年后同一个 id 指向另一份图集；表示因此同时携带笔刷清单，并允许把实际 brush PNG 一起封进容器。

精修分支只能做有界增量#

精修分支要求每根笔触恰好四个控制点，把它解释为三次 Bézier。优化参数不是直接替换原值，而是围绕基础计划建立有界增量：

  • 控制点位移经 tanh 限制，端点权重更小，避免路径整体漂离目标区域。
  • 宽度、载漆与厚度按指数比例变化，并钳在基值与全局上下界之间。
  • 压力、透明度与湿度在 logit 空间平移，输出仍落在 [0, 1]。
  • 颜料只在原先激活的三个槽位内做 softmax，不在优化中突然换入另一种颜料。
  • 曲率与全部 delta 进入正则项，阻止优化器用极端折线或异常材质值追逐像素误差。

多尺度优化按 tile 执行。稠密笔触贡献使用 gradient checkpoint，以重算换显存；检查点路径保存的仍是完整计划文件，任务取消时可以回到最近一个有效计划，而不是只留一份无法解释的优化器张量。

可微目标包含颜色、结构、方向和多尺度相似度，但它只能改变计划允许表达的参数。离散笔刷类型、图层拓扑和颜料槽身份仍由基础计划决定。这项限制让结果保持可重放，也限制了精修能修正的问题范围。

光谱颜料在两个分支保持同一语义#

颜料表同时保存显示 RGB 与波段反射率。RGB 先转换成受限反射率曲线；混合时不直接平均颜色，而是进入 Kubelka–Munk 的 (K/S) 形式：

KS=(1−R)22R\frac{K}{S} = \frac{(1 - R)^2}{2R}SK​=2R(1−R)2​

各颜料按质量权重混合 (K/S)，再恢复反射率：

R=1+KS−(KS)2+2KSR = 1 + \frac{K}{S} - \sqrt{\left(\frac{K}{S}\right)^2 + 2\frac{K}{S}}R=1+SK​−(SK​)2+2SK​​

实时分支为带宽和循环上限使用最多 8 个颜料、8 个波段；精修分支可使用 31 波段进行优化。二者的采样精度不同，但共享“每根笔触由最多三种颜料及权重组成、终局按减法颜料模型解释”的语义。

D3D12 Material Pass 按像素累积颜料质量，再对每个波段计算混合反射率并投影回 RGB。没有颜料质量时使用抽象底色；有颜料时根据覆盖、质量和颜料误差决定真实颜料贡献。这样 underpaint 与笔触沉积的职责保持分开。

湿度和厚度属于材质状态#

Raster Pass 不只写颜色。画布状态包含覆盖、高度、厚度与湿度，另有方向图与逐颜料质量缓冲。压力与载漆影响沉积和拾色，厚度形成宏观高度，笔刷纹理形成细尺度鬃毛起伏，湿度则进入混合、干燥和高光。

共享终局由这些状态生成：

  • Albedo：抽象底色与 Kubelka–Munk 颜料按覆盖混合。
  • Height / Thickness：笔触沉积与拾色后的物质量。
  • Normal：平滑高度的宏观梯度加原始高度的鬃毛梯度。
  • Roughness：湿度、厚度、覆盖和方向变化共同调制。
  • AO：高度邻域的凹陷关系。
  • Beauty：非金属 GGX、笔触方向各向异性和湿膜宽高光。

干燥降饱和发生在颜料沉积和底色混合之后，并同时受覆盖、湿度与非焦点程度影响。它不是对最终 Beauty 做一次全图灰化。湿颜料保留更多颜色，干颜料提高散射；湿膜还降低局部粗糙度并增加一层宽高光。

这也是共享终局的价值。如果两个后端各自把 wetness=0.7 解释成不同 BRDF，同一份计划仍然不能跨后端比较。现在优化器只决定湿度参数，最终物理外观由同一材质实现解释。

缓存键必须覆盖行为版本#

处理链按阶段缓存：

每个参数只失效实际受它影响的阶段。灯光参数属于 paint_state，不应让前面的笔触规划失效；调色板与 seed 则会影响计划。

还有一项容易遗漏的输入：代码行为本身。分析、材质或规划器公式变化后，即使用户参数完全相同，旧缓存也不再代表当前程序。因此要把一个管线行为版本号纳入相关 key；改变行为而不递增它，会得到“代码已改、画面完全没变”的假诊断。

缓存不是兼容路径。构建失败、能力不足或合同不符时，不会返回旧阶段结果假装成功。事务化导出也先在临时位置生成全部材质、manifest 与 OilPack，校验字节数和 SHA-256 后才发布；取消任务不暴露半成品。

验证口径#

这类表示的核心验收是独立回放。已保存的计划重新读取后，通过同一材质终局生成 Beauty；固定验收语料中，原生成结果与独立回放的平均和最大绝对误差均为 0.0。这证明计划包含终局需要的全部图元、颜料与笔刷语义。

两个后端的性能数字不能直接横比：

  • D3D12 峰值通常通过 DXGI 本地显存用量相对基线采样。
  • CUDA 优化峰值来自 PyTorch 分配器统计。
  • 实时分支计时可以关闭缓存和导出，只测生产管线；精修分支还包含多尺度迭代、checkpoint 与进度事件。

这些数字可以各自判断是否通过目标门槛，不能相减后解释成某后端“多用了多少显存”。跨 API 测量若没有统一观测层，比较结论应停在各自 SLA。

结论#

有界参数化换来可重放，代价是精修只能修正表示已经允许表达的问题。离散的笔刷类型、图层拓扑和颜料槽身份由基础计划决定：如果规划阶段把一片区域的方向场判断错了，精修再怎么压像素误差也纠不回来——那是要改规划器，不是调优化器。判断问题落在哪一侧，本身就是这套分层带来的能力。

确定性回放的 0.0 误差只覆盖“表示是否完整”，不覆盖“表示是否合适”。它证明终局需要的语义全在计划里，不证明这套笔触参数化足以描述目标画面。

跨 API 的测量同样有边界。D3D12 与 CUDA 的显存峰值来自两套互不相通的统计口径，各自判断是否越过门槛可以，相减后解释成“某后端多用了多少”不行。没有统一观测层时，比较结论应当停在各自 SLA。

这套分层可迁移的前提只有两条：中间表示能脱离任一后端独立存在，且材质终局只实现一次。任何一个后端私下补一套自己的近似着色，可归因性立刻失效——此时共享的就又只是一张图片了。
